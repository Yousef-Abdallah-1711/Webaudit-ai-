## 1. Status definitions
Unchanged from v5 §2 (`PLANNED` … `KILLED`; no status added or removed). Edges: `PLANNED→ADMITTED`, `ADMITTED→DISPATCHED`, `DISPATCHED→RUNNING`, `ADMITTED→REFUSED`, `PLANNED→REFUSED`, `DISPATCHED→REFUSED` (DEC-013 E1, DEC-064: only while the start gate is unreleased and no effect is authorized), `RUNNING→{COMPLETED,FAILED,CANCELLED,KILLED}`. `KILLED` only from `RUNNING`. `TELEMETRY`: `PLANNED→COMPLETED` at generation.

## 2. Dispatch sequence (replaces `execution-runtime-contract.md` steps 0–4)
1. Enqueue `{executionUnitId}` when eligible; unit `PLANNED`; no lease.
2. **Pickup**: re-read from PostgreSQL; non-`PLANNED` ⇒ acknowledge, change nothing.
3. **Engine-local capacity check** before any F07 call; failing ⇒ delay/requeue (unit stays `PLANNED`).
4. **`claimUnitHost`** (§3). Not `CLAIMED` ⇒ stop.
5. Engine guards ⇒ `REFUSED` from `PLANNED` with §6 precedence.
6. **Pre-F07 re-read** (§6 procedure), then **F07 admission** with `executionId = ExecutionUnit.id` (008 interim identity, now final): `STOP` ⇒ `REFUSED(f07 reason)`; `PROCEED` ⇒ Class L lease held. Start the host loop (§7).
7. `CAS PLANNED→ADMITTED`. If it loses, the host calls `f07_release_leases_by_execution(unitId)` for the lease it just created (idempotent) and stops.
8. Engine proofs in `ADMITTED`; refusal ⇒ `REFUSED` from `ADMITTED`; then re-evaluate §6.
9. `CAS ADMITTED→DISPATCHED`.
10. Fork the child under the **start gate** (no credential/work order/external resource); child exits on parent loss and after `startGateTimeoutMs` (provisional technical default 30 000 ms) without gate release. These two rules are new requirements on engines.
11. `CAS DISPATCHED→RUNNING`; on loss, terminate the child and write nothing.
12. Arm the parent hard stop; **only then** perform effects, each through §5.
13. Finalization (§8).

## 3. Host claim
`ExecutionUnitHostClaim(id, executionUnitId, attempt, scanPlanId, userId, hostInstanceId, claimTokenHash, claimSeq, acquiredAt)`, `@@unique([executionUnitId, attempt])`, scalars only, never updated. Token: ≥128-bit CSPRNG generated by the host, stored only as SHA-256, sent as a bind parameter, never logged/queued/emitted/passed to the child. `hostInstanceId` is a label. `claimUnitHost(executionUnitId, hostInstanceId, tokenHash)`: one transaction — lock the unit row, require `PLANNED`, plan `RESOLVED`, scan non-terminal, evaluate §6 on the statement clock (`clock_timestamp()`), insert the claim. Results `CLAIMED | ALREADY_CLAIMED | REFUSE(reason) | NOT_CLAIMABLE`; `REFUSE(reason)` only when §6 yields a refusal **and no stop is pending**. No takeover, no resume, no heartbeat. Workers share one DB role today: non-conforming/compromised worker resistance is **not claimed** (AR-13; closed only when runtimes connect as the 008 roles).

## 4. Status CAS and lock order
**CAS form**: one conditional `UPDATE … WHERE id AND status = :from AND EXISTS(claim row matching attempt, `claimTokenHash = sha256(:token)`, `hostInstanceId`)`; 0 rows = transition lost. Class L additionally (second statement, same transaction): `SELECT 1 FROM "AdmissionLease" WHERE "executionId" = :unit AND "releasedAt" IS NULL AND "reclaimedAt" IS NULL FOR SHARE`; no row ⇒ roll back (lease lost). Class N omits it.
**Lock order (one global order; supersedes v5 §5.4 and extends 008 DEC-050)**: `ExecutionUnit` row → scope advisory locks (`f07_lock_scope`) → `BudgetCounter` → `AdmissionLease` → `KillSwitchState` → inserts. Admission (F07) runs in its own transaction and never locks a unit row; finalization locks the unit first and then follows the 008 order inside `f07_release_leases_by_execution`; the host CAS locks unit → lease(share), a strict prefix-consistent subsequence. No operation locks a lease/counter before a unit row, so no cycle among them. Reclaim/reconcile never wait (008). The shared-lease check protects the commit instant only.

## 5. Per-effect authorization (DEC-051 A)
`EffectAuthorization(id, executionUnitId, attempt, kind, ordinal, userId, state AUTHORIZED|CONFIRMED|ABANDONED, authorizedAt, confirmedAt)`, `@@unique([executionUnitId, attempt, kind, ordinal])`. `authorizeEffect(unit, claim, kind, ordinal)` — one transaction: `SELECT … FROM "ExecutionUnit" WHERE id FOR SHARE`; verify `status = RUNNING`, claim, scan non-terminal, deadline (§6 order), Class L renewable lease `FOR SHARE`; insert the row `AUTHORIZED` (idempotent on the unique key) and commit. Only then does the effect run. `confirmEffect` sets `CONFIRMED`. Finalization needs the unit row exclusively, so it commits strictly before or after an `authorizeEffect`, never between.
**Guarantee (bounded)**: no *new* authorization after terminalization; at most already-authorized in-flight effects remain; the effect itself cannot be recalled. Engines with their own ledger (SPEC 012) conform to the same lifecycle. `onUnitExpired` returns `TERMINATED` only if no `AUTHORIZED` row lacks `CONFIRMED`/`ABANDONED`, else `PENDING`. A row still `AUTHORIZED` after its unit is terminal is marked `ABANDONED` by finalization (never treated as executed for billing; DEC-062 unchanged).

## 6. One cause-precedence procedure for every writer (DEC-058)
`classifyPreRunCause(unit)`, used verbatim by claim, step-0, post-F07 re-check, engine guards, host loop, sweep/`expirePlanUnits`, `authorizeEffect`: (1) unit terminal → no-op; (2) stop pending (any `KillSwitchState` row `REQUESTED|ACKNOWLEDGED|STOPPED` for the unit's execution, scan, grant, target, tenant or platform scope; `STOPPED` for `(EXECUTION,id)` refuses unconditionally) → `KILL_SWITCH_PENDING` pre-`RUNNING`; (3) scan `CANCELLED|FAILED|TIMED_OUT` → `SCAN_CANCELLED|SCAN_FAILED|SCAN_DEADLINE_EXPIRED`; (4) `now ≥ effectiveDeadlineAt` → `SCAN_DEADLINE_EXPIRED`; (5) remaining `< timeoutPolicyMs + hardStopMarginMs` → `SCAN_DEADLINE_INSUFFICIENT`. A refusal by writers that cannot name `KILL_SWITCH_PENDING` is **not written when a stop is pending** (the unit proceeds to F07, which refuses with the stop reason, or waits for the sweep).
The pure arithmetic of causes 4–5 is `dispatchDeadlineDecision` (implemented, tested); causes 1–3 read database state.

## 7. Host loop (≥ every 5 s until finalization)
1. Unit terminal ⇒ stop, kill child, write nothing. 2. Class L: renew lease; 0 rows ⇒ `leaseLost`. 3. `classifyPreRunCause`. 4. `leaseLost` ⇒ abort, kill child, **no finalization**; if a stop is pending the host may only `acknowledgeStop` (idempotent); the sweep finalizes. Stop pending, lease held ⇒ `acknowledgeStop` → abort → kill child → owner finalizes (pre-`RUNNING`: `REFUSED(KILL_SWITCH_PENDING)`; `RUNNING`: existing KILLED/CANCELLED mapping). Scan terminal/deadline expired, lease held ⇒ owner finalizes `REFUSED(SCAN_*)` pre-`RUNNING`, existing U-1 behaviour in `RUNNING`.
**Stop lifecycle (aligned with 008)**: after finalization the **finalizer** calls `f07_ack_stop_by_authority(unitId)` in the same transaction when a stop is pending (DEC-048 A); `STOPPED` is written only by `f07_record_stopped` / the stranded-stop reconciler once `f07_scope_has_live_execution` is false (DEC-049 A). No call order beyond this is mandated for the host.

## 8. Single finalization authority (DEC-047 A)
`finalizeExecutionUnit` is **one logical operation** with one database body (`fahes_finalize_unit`, SQL) that: validates the guarded edge against the transition-policy table; writes the terminal status once (idempotent on re-entry, returning the prior outcome); sets `completedAt`/`failureClass`/`skippedReason`/`blockedByExecutionUnitId`; runs `f07_release_leases_by_execution` in the same transaction; acknowledges a pending stop by authority; marks unconfirmed `EffectAuthorization` rows `ABANDONED`; and applies one-level `BLOCKED` propagation to direct dependents (`dependentsToBlock` rule, implemented and tested). Any entry point (worker, sweep, SPEC 012 `sec_finalize_*`) calls this body or a thin wrapper of it; an equality test asserts every wrapper's edge set equals the policy table. `runtime-finalization-contract.md` rule 1 is read: "the only *logical* path; one database body".

## 9. Recovery limits (stated, not hidden)
A unit whose host is lost before `RUNNING` is not resumed; it ends at the plan-deadline sweep (≤ 6 h ceiling + one sweep interval). Lease slot reclamation ≈ 90 s applies only to a crashed holder while the 60 s maintenance sweep runs; it bounds slot reclamation, not host authority. A stale-but-live host stops at its next loop read (≤ 5 s) or at its first failed CAS/`authorizeEffect`. Inert-child exit and hosting-failure backstop are engine obligations (AR-22), unproven here.

## 10. Guarantee classes
Database-enforced for the mandated statement forms (one claim per (unit, attempt); one winner per status edge; no new `authorizeEffect` after terminalization; finalization+lease release atomic; idempotent finalization). Conformance-dependent: that every writer uses these forms (shared worker role until the 008 roles are in use). Not claimed: compromised-worker resistance, effect-after-terminalization of an already-authorized effect, deadlock freedom beyond the stated order, recovery faster than §9.
