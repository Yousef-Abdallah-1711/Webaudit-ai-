# Tasks: Source / Backend / Database / Automated Code Testing Platform

**Input**: Design documents from `specs/011-source-backend-database-testing-platform/`

**Prerequisites**: plan.md, spec.md (FR-001..FR-158, SC-001..SC-010), research.md, data-model.md, quickstart.md, contracts/ (19 contracts). Landing paths are those in plan.md "Planned Source Code (repository root; NOT created by this pass)".

**Tests**: included and written FIRST. Per the Constitution's Development Workflow and AGENTS.md, every implementation task is preceded by test tasks that must be run and confirmed failing for the intended reason before the implementation lands. Fixture tasks name the contract they prove, the expected verdict/reason code, and where they run: **fake provider** (any machine) or **real provider, Linux CI only** (hostile fixtures never execute on a developer workstation, FR-061).

**Organization**: Setup, Foundational (blocking registries and writers), then one phase per user story (US1 static analysis P1, US2 hostile-code execution P1, US3 database/migration P2, US4 backend testing P2, US5 reverify/correlation/AI P3), then Polish. The 29 "testing the tester" fixtures plus prompt-injection fixtures and runner-exit-0-without-tests each have an explicit task inside the story that owns the behavior.

**Gating (read before dispatching any task)**:

- Implementation of this spec is gated on the SPEC 007, 008, 009 and 010 runtime implementations having landed (FR-138). `EvidenceKind`, `ExecutionUnit`, `Evidence`, `Artifact`, `IdempotentClaim`, F01 and F07 do not exist in `schema.prisma` today. No task may create an interim table or private substitute for them. The additive enum migration (below) MUST be sequenced after the 009 and 010 migrations.
- Production activation of any `SOURCE_EXECUTION` behavior is gated on Execution Plane Isolation Acceptance Bar (IAB) acceptance and external penetration review (FR-040, FR-041, FR-058). Until then the platform behaves as `DisabledProvider`; there is no fallback to any weaker isolation (including `apps/sandbox-runner`). US2 tasks build and test the machinery; none of them activates it in production.
- All implementation is delegated to Codex (`/codex-delegate`, per CLAUDE.md); Claude re-verifies the diff and the real gate commands. Every task below is self-contained with exact paths and the FR/contract it implements.
- Nothing here changes existing capabilities, queues, pricing, scan-creation UX or report format (FR-133). All new behavior sits behind three default-off flags.
- None of these tasks is executed by the planning pass; all boxes stay unchecked.

**Format**: `- [ ] T### [P] [USn] Description with exact file path (FR-xxx; contract)`. `[P]` = different files, no dependency on an incomplete task. `[USn]` only in story phases. Contract names omit the `.md` suffix.
